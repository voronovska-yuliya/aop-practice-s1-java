# Практична робота №11 — Алгоритми та складність

## Виконані завдання

1. **Missing Number** — пошук відсутнього числа в масиві за допомогою формули суми арифметичної прогресії.
2. **Majority Element** — пошук елемента, який зустрічається більше ніж половину разів, за допомогою алгоритму голосування Бойєра — Мура.

## Відкрита дискусія

1. **Що означає складність алгоритму O(n)?**

O(n) означає, що кількість операцій зростає приблизно пропорційно розміру вхідних даних.

2. **Чому для оцінювання складності рахують кроки, а не секунди?**

Тому що швидкість виконання залежить від комп'ютера, процесора та інших умов. Кількість кроків дає змогу порівнювати алгоритми незалежно від пристрою.

3. **Як спростити O(n² + n)?**

Залишається O(n²), оскільки при великих значеннях n квадратична складова зростає значно швидше за лінійну.

4. **Якщо алгоритм обробляє 1000 елементів за 10 секунд, скільки приблизно потрібно для 2000 елементів при O(n)?**

Приблизно 20 секунд, тому що кількість елементів збільшилася вдвічі.

5. **Якщо алгоритм обробляє 1000 елементів за секунду, скільки часу потрібно для 1 000 000 елементів?**

Приблизно 1000 секунд, тобто 16 хвилин 40 секунд.

6. **Чи може алгоритм із гіршою асимптотичною складністю працювати швидше на малих обсягах даних?**

Так. На малих обсягах даних вплив можуть мати сталі витрати, кількість додаткових операцій та особливості реалізації.

7. **Чим відрізняється теоретична складність від вимірювання часу виконання?**

Теоретична складність описує, як змінюється кількість операцій зі збільшенням вхідних даних. Вимірювання часу показує, скільки конкретна програма працює на певному комп'ютері.
